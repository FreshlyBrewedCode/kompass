# `edges.parquet`: the contract between pipeline and engine

One row per edge of the routable graph: a stretch of an OSM way between two junctions. The Python
pipeline writes it, the Rust engine reads it, the overlay map tiles are cut from it. The columns,
dtypes and enum labels are defined in exactly one place, `pipeline/src/kompass_pipeline/schema.py`;
the tables below are generated from it (`kompass-pipeline docs --write`) and a test fails when they
drift.

## Format

- GeoParquet 1.1: the geometry is a WKB LineString in EPSG:4326 (lon/lat, float64), zstd compressed,
  row groups of 128 k rows. Only simple dtypes: uint8/16/32, int8, int64 ids, float32, bool, string.
  Low-cardinality strings (`surface`, `name`, ...) are dictionary-encoded on disk.
- **Sorted by `hilbert_z16`**: the Hilbert index of the edge midpoint on the web-mercator z16 tile
  grid. Every tile at zoom <= 16 is a contiguous run of rows, so the graph tile compiler can cut
  tiles on any quadtree level and the row groups have tight bounds.
- `edge_id` is the row number. It is **not stable across builds**; the overlay tiles, the graph
  tiles and everything matched against the edges (history) must come from the same build. The
  `kompass:build_id` metadata ties them together: the overlay tiles carry it in their description
  and `manifest.json` repeats it.
- Physical units stay physical (metres, percent, km/h); quantising is the tile compiler's job.
  Shares are uint8 percent, 0..100.
- Dead ends (bridges, pockets) are not in the file: they depend on the profile's hard constraints,
  so the engine finds them. Legally doubtful ways are kept and marked (`bike_access`), never
  dropped: the profile decides.
- Nothing is derived that the engine can compute from these columns, with one exception: elevation
  and the context shares need the DEM and landuse polygons, so they are precomputed.

A column added later (`layer`) does not bump the schema version: the engine's compile reads the
columns it knows by name and ignores others, so it keeps reading older and newer files. The version
changes only for what the engine must know about.

## Key-value metadata

| key | value |
|---|---|
| `kompass:schema_version` | the schema version (integer, as a string); bumped for every change a reader must know about |
| `kompass:enums` | JSON `{column: {code: label}}`, the enum code tables below |
| `kompass:build_id` | the id of the build that wrote the file |
| `geo` | GeoParquet metadata |
